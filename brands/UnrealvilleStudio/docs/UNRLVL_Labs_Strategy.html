La planta de producción de contenido de UNRLVL para los próximos 3 años. Este documento es la referencia canónica para decisiones de adopción de modelos.

Premisa estratégica

No elegimos APIs.
Diseñamos la planta de producción.

Cada modalidad usa el mejor modelo de su categoría. Los modelos son intercambiables. La arquitectura no.

El IID Content Engine es el sistema nervioso central. Los Labs son los órganos especializados. La estrategia de modelos determina qué tan potentes, económicos y mantenibles son esos órganos.

La decisión central

fal.ai como
Media Bus

fal.ai no es un proveedor de video. Es el aggregator de modelos de medios generativos más completo del mercado: una sola API key, un mismo patrón de código, 50+ modelos de imagen/video/audio/avatar.

Cambiar de modelo es reemplazar un string en la base de datos. Nada más. Cuando Kling 3.0 supere a Kling 2.5 en calidad, cambias una línea en lab_configs.default_params. No hay deployment, no hay código nuevo.

¿Genera texto / copy? → Claude (Anthropic directo)
¿Genera imagen estática? → fal.ai (Imagen 3 o FLUX)
¿Genera video <30s social? → fal.ai / Kling Turbo Pro
¿Talking head / presenter? → HeyGen API
¿Audio / voz de marca? → ElevenLabs API
¿Composición multi-modal larga? → PodcastLab + Creatomate
¿Modelo completamente nuevo? → Verificar en fal.ai primero

Regla de oro

Cuándo cambiar un modelo

Un modelo se reemplaza SOLO cuando:
  • El nuevo modelo es ≥20% mejor en calidad para el caso de uso específico del lab
  • El nuevo modelo es ≥30% más económico a igual calidad
  • El provider actual tiene un incidente de servicio crítico (downtime, pricing shock, API break)
  • El pipeline de evaluación A/B muestra preferencia estadística por el nuevo modelo

No se cambia por hype, por novedad, ni por "salió una versión nueva". El default_model vive en lab_configs.default_params — cambiar un modelo es una query SQL, no un deployment.

¿Por qué no un modelo multimodal único?

La pregunta natural es si no sería más simple usar un solo modelo que haga todo. La respuesta es no:

1. Ningún modelo unificado es el mejor en cada modalidad. Claude escribe mejor copy que Gemini. Kling genera mejor video social que cualquier modelo de texto. ElevenLabs produce mejor voz que cualquier modelo multimodal. Los modelos especializados siempre ganan a los generalistas en sus dominios.

2. Control de costos imposible con modelos unificados. Un modelo multimodal cobra por la pieza completa. El enfoque modular cobra solo por lo que se usa.

3. Sustitución trivial en el modelo modular. Si mañana Anthropic lanza algo mejor para copy, cambias CopyLab. El resto del pipeline no se toca.

Excepción: evaluación y scoring de contenido ya generado (ej: Gemini Vision evaluando si una imagen cumple criterios de marca). Eso es un caso válido para una capa de QA futura.
